# Próximas etapas

Esta é uma sequência proposta. O responsável pode ajustar a ordem ou o escopo.

## 1. Preparação do repositório — etapa atual

- Organizar os requisitos já discutidos.
- Separar confirmações de propostas e dúvidas.
- Manter documentos sobre produto, regras, visual e decisões.
- Reaproveitar o repositório autorizado na conta `zakbodie`, preservando a versão anterior em uma branch de backup.
- Concluir a renomeação administrativa para `mc-segurancas` quando a configuração do GitHub estiver acessível.

Esta etapa contém documentação, sem uma aplicação, framework, banco de dados provisionado ou implantação.

## 2. Design e fluxos

Escolher referências, identidade visual e navegação. Desenhar a visão diária, o lançamento de uma falta e a seleção de pessoas para FT. Validar os estados de presença, folga e sincronização.

Resultado esperado: direção visual e fluxos entendidos pelo responsável.

## 3. Regras e escopo inicial

Resolver os itens essenciais de [decisões em aberto](04-decisoes-em-aberto.md), especialmente escala noturna, exceções, prioridade de FT e permissões. Definir quais funções entram na primeira versão.

Resultado esperado: regras com exemplos fictícios e escopo documentado.

## 4. Escolha técnica

Comparar plataformas e custos conforme o escopo, os aparelhos e a necessidade de sincronização. Escolher a estrutura técnica sem provisionar serviços pagos por suposição.

Resultado esperado: decisão de plataforma, arquitetura e operação.

## 5. Implementação e piloto

Iniciar quando houver orientação para desenvolver. Implementar o escopo acordado e verificar os fluxos principais, virada de datas, correções e atualização entre celulares. Fazer o piloto com dados fictícios ou com dados operacionais autorizados em ambiente apropriado.

Resultado esperado: primeira versão utilizável e revisada antes de ampliar o uso.
